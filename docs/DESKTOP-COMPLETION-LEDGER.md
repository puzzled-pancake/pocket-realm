#### R1-11 — low
**What:** Desktop `friendAccess` lazy getter is a check-then-act race: two concurrent first callers (the state watcher coroutine and a UI/ban path) can each construct a FriendAccessController; one is silently dropped, so UI state flows (_freshToken/_status/invites) and audit writes can land on an instance nobody drives.
**Evidence:** DesktopAppModel.kt:330-338 — `@Volatile private var friendAccessInstance ... get() = friendAccessInstance ?: FriendAccessController(...).also { friendAccessInstance = it }` — volatile makes the reference visible, not the check+construct+assign atomic. Concurrent first-touchers: the friendAccessWatcher collector (DesktopAppModel.kt:340-355, Dispatchers.Default, calls friendAccess.onRuntimeChanged on the very first emission) and the guest-ban audit lambda (DesktopAppModel.kt:1008-1010, friendAccess.store) / any screen capturing model.friendAccess. The loser's StateFlows diverge from the winner's (listenerState shows Off while the winner binds; createInvite on the captured loser still writes the shared store file so rows converge, but token/status surfaces do not).
